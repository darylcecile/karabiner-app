# ADR-001: Use a native iPadOS SwiftUI and XcodeGen scaffold

## Status
Accepted

## Date
2026-05-22

## Context
Karabiner is an iPad-first agentic IDE. The PRDs require a native, professional iPad experience with split views, keyboard shortcuts, touch, pointer, Pencil, accessibility, secure auth, and App Store alignment. Research for the initial implementation confirmed the local toolchain as Xcode 26.5 with Swift 6.3.2.

The repository foundation currently includes an XcodeGen `project.yml` scaffold plus separate app, core, UI, unit test, and UI test target directories. Other feature work may still be in progress, so this ADR records the scaffold direction rather than claiming completed product behavior.

## Decision
Use a native iPadOS Swift app scaffold generated by XcodeGen:

- SwiftUI is the default app shell for navigation, settings, sheets, toolbars, and adaptive iPad layouts.
- UIKit/TextKit 2 remains the planned escape hatch for pro editor, diff, focus, keyboard, and custom input surfaces that exceed SwiftUI's current strengths.
- Keep product/domain logic outside SwiftUI where practical so service, provider, persistence, and testing layers can evolve without rewriting UI.
- Treat `project.yml` as the source of truth for the initial target graph instead of hand-editing an `.xcodeproj`.

## Alternatives Considered

### Hand-maintained Xcode project
- Pros: Familiar to many iOS developers; no generator dependency.
- Cons: Harder for agents and reviewers to diff; project-file churn is easy to introduce.
- Rejected because XcodeGen gives a reviewable, reproducible scaffold.

### Swift Package-only application structure
- Pros: Simple for libraries and command-line validation.
- Cons: Does not represent an iPad app target, UI test target, resources, entitlements, or App Store packaging as clearly.
- Rejected for the application shell, though package-style modularity remains useful inside targets.

### Web, PWA, or Catalyst-first shell
- Pros: Faster cross-platform reuse.
- Cons: Conflicts with the PRD's native iPad UX, input, accessibility, and App Store posture.
- Rejected for V1 core product experience.

## Consequences
- Project changes are visible in YAML and can be regenerated consistently.
- SwiftUI can ship the shell quickly while UIKit/TextKit 2 remains available for editor-grade surfaces.
- Contributors and agents must avoid editing generated Xcode project files directly.
- The scaffold can support future service/UI/testing work without implying that those layers are complete today.
